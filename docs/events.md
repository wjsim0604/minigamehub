# 이벤트/메시지 목록 (events.md)

> 서비스 간 비동기 통신에 쓰는 이벤트의 목록과 의미를 정의합니다.
> 실제 스키마(JSON Schema 등)는 `contracts/`에 두고, 여기에는 목적과 흐름을 설명합니다.
> **이벤트는 먼저 정의한 뒤 발행/구독을 구현합니다.** 하위 호환을 깨는 변경은 버전을 올리고 사람에게 먼저 확인합니다.

> **현재 상태 (2026-10-14):** 1차(MVP)는 백엔드 서비스가 없으므로 이벤트가 **없습니다** (ADR-0003 제안).
> 2차(랭킹)에서 필요 여부를 판단해 정의할 예정입니다. 후보는 `architecture.md` 5장 "이벤트 후보"에만 기록하며, 확정 전까지 이 목록에 넣지 않습니다. 메시지 브로커 도입 여부도 미정입니다.

## 1. 공통 규칙 (이벤트 도입 시 확정)
- 브로커: `<미정 - 2차에서 이벤트가 필요할 때 결정>`
- 이벤트 이름: `도메인.동사(과거형)` (예: `user.deleted`)
- 토픽/큐 이름 규칙: `<예: {domain}.{event}.v1>`
- 소비자는 **멱등하게** 처리해야 합니다 (같은 이벤트가 2번 와도 결과가 같아야 함).
- 순서 보장이 필요한 경우 기준 키: `<예: userId>`

### 공통 이벤트 봉투(envelope)
```json
{
  "eventId": "uuid",
  "eventType": "user.deleted",
  "version": 1,
  "occurredAt": "2026-01-01T00:00:00Z",
  "producer": "user-service",
  "traceId": "...",
  "data": {}
}
```
