# 요구사항 (requirements.md)

> 작성: planner 에이전트 / 검토: 사람
> 요구사항이 바뀌면 이 문서를 먼저 수정하고, 영향받는 `architecture.md`, `api.md`, `events.md`, `contracts/`를 함께 갱신합니다.
> 최종 수정: 2026-10-14 (초안, 사람 검토 전)

## 1. 배경과 목표
- 해결하려는 문제: 가볍게 즐길 수 있는 미니게임이 여러 사이트·앱에 흩어져 있고, 설치나 가입 없이 바로 하기 번거롭다.
- 목표
  - 설치·가입 없이 브라우저에서 바로 여러 미니게임을 골라 플레이할 수 있는 웹 서비스를 제공한다.
  - 1차(MVP): **2048**, **점프 게임**(장애물을 점프로 피하는 무한 러너형) 2종을 데스크톱·모바일 브라우저에서 제공한다.
  - 새 게임을 기존 코드 수정 최소화로 추가할 수 있는 구조(게임 레지스트리)를 갖춘다.
  - 2차: 회원과 게임별 랭킹(리더보드)을 추가한다.
- 성공 기준(측정 가능하게): `<미정 - 사람 결정 필요. 예: 홈 진입 후 게임 시작 비율 60% 이상, 세션당 평균 플레이 횟수 3회 이상>`
  - 측정 수단(분석 도구 도입 여부)도 미결정 (6장 참고)

## 2. 사용자와 시나리오
| 사용자 유형 | 설명 | 주요 시나리오 |
|---|---|---|
| 일반 사용자(비로그인) | MVP의 유일한 사용자 유형. 가입 없이 접속해 플레이 | 홈에서 게임 목록 확인 → 게임 선택 → 플레이 → 게임오버 → 재시작 또는 홈으로 돌아가 다른 게임 선택 |
| 모바일 사용자 | 스마트폰 브라우저로 접속 | 터치(스와이프/탭)로 조작, 세로 화면에서 플레이 |
| 회원(2차) | 로그인한 사용자 | 게임오버 시 점수 제출 → 게임별 리더보드에서 순위 확인 |
| 관리자 | 해당 없음 (MVP·2차 모두 관리자 기능 없음, 게임 추가는 코드 배포로 처리) | - |

### 대표 시나리오 (MVP)
1. 사용자가 사이트에 접속하면 홈에 게임 카드(썸네일, 이름, 설명)가 보인다.
2. "2048" 카드를 눌러 게임 화면으로 이동해 방향키(모바일은 스와이프)로 플레이한다.
3. 더 이상 움직일 수 없으면 게임오버 화면에 이번 점수와 최고 점수가 표시되고, "다시 하기"로 재시작한다.
4. 홈으로 돌아가 "점프 게임"을 선택하고 스페이스(모바일은 탭)로 점프하며 플레이한다.
5. 브라우저를 닫았다 다시 와도 게임별 최고 점수가 유지된다(같은 브라우저 기준).

### 상세 (기능별로 추가)

#### FR-001 게임 목록(홈)
- 사용자 스토리: 사용자로서, 접속하자마자 어떤 게임이 있는지 한눈에 보고 싶다. 그래서 바로 하고 싶은 게임을 고를 수 있다.
- 인수 조건(Acceptance Criteria)
  - [ ] 사용자가 처음 접속하는 첫 화면(`/`)은 게임 선택 화면이다. 별도의 랜딩·소개·로그인 화면을 거치지 않는다. (사람 확정)
  - [ ] 홈(`/`)에 게임 레지스트리에 등록된 모든 게임이 카드로 표시된다 (MVP: 2048, 점프 게임 2개).
  - [ ] 각 카드에는 썸네일, 게임 이름, 한 줄 설명이 표시된다.
  - [ ] 카드 목록은 레지스트리 데이터에서 생성되며, 레지스트리에 게임을 추가하면 홈 코드 수정 없이 카드가 추가된다.
  - [ ] 각 카드에 해당 게임의 로컬 최고 점수가 있으면 함께 표시된다 (없으면 표시하지 않거나 "기록 없음").
  - [ ] 데스크톱(가로 1280px)과 모바일(가로 360px)에서 카드가 잘리거나 겹치지 않는 반응형 레이아웃이다.
  - [ ] 로그인 없이 바로 접근할 수 있다.
- 화면/흐름: 홈 화면 1개 (헤더: 서비스 이름 / 본문: 게임 카드 그리드). 와이어프레임 `<미작성>`
- 예외 상황
  - 썸네일 이미지 로드 실패 시 기본 대체 이미지 또는 게임 이름 텍스트를 표시한다.
  - 레지스트리가 비어 있으면 "준비 중인 게임이 없습니다" 안내를 표시한다.

#### FR-002 게임 선택/진입
- 사용자 스토리: 사용자로서, 카드를 눌러 바로 게임에 들어가고, 끝나면 쉽게 목록으로 돌아오고 싶다.
- 인수 조건(Acceptance Criteria)
  - [ ] 카드(또는 카드 내 "플레이" 버튼)를 클릭/탭하면 해당 게임 경로(`/games/{gameId}`)로 이동한다.
  - [ ] 게임 경로 URL을 직접 입력하거나 공유받아 열어도 해당 게임이 바로 열린다.
  - [ ] 게임 화면에 홈으로 돌아가는 버튼이 있고, 브라우저 뒤로 가기로도 홈으로 돌아갈 수 있다.
  - [ ] 레지스트리에 없는 `gameId` 경로로 접근하면 "게임을 찾을 수 없습니다" 화면과 홈 이동 버튼을 표시한다 (404).
  - [ ] 게임 코드는 해당 게임 화면에 진입할 때 로드된다(홈에서 모든 게임 코드를 미리 내려받지 않음).
  - [ ] 게임 화면을 벗어나면 진행 중인 게임 루프·이벤트 리스너가 정리되어 다른 화면에 영향을 주지 않는다.
- 화면/흐름: 홈 → 게임 화면(`/games/2048`, `/games/jump` 등, 최종 id는 레지스트리에서 확정) → 홈
- 예외 상황: 게임 코드 로드 실패(네트워크 오류) 시 오류 안내와 "다시 시도" 버튼을 표시한다.

#### FR-003 2048 플레이
- 사용자 스토리: 사용자로서, 방향키나 스와이프로 타일을 밀어 같은 숫자를 합치며 높은 점수를 노리고 싶다.
- 인수 조건(Acceptance Criteria)
  - 시작
    - [ ] 4x4 보드에서 시작하며, 시작 시 빈 칸 중 무작위 2곳에 타일이 생성된다.
    - [ ] 새 타일은 2(90%) 또는 4(10%)로 생성된다. `<확률은 일반적 규칙 기준 가정, 변경 가능>`
  - 조작
    - [ ] 데스크톱: 키보드 방향키(↑ ↓ ← →)로 4방향 이동한다. 게임 화면에서 방향키 입력 시 페이지가 스크롤되지 않는다.
    - [ ] 모바일: 보드 위에서 상/하/좌/우 스와이프로 이동한다. 일정 거리(예: 30px) 미만의 터치 이동은 무시한다.
    - [ ] 보드 위에서 스와이프하는 동안 페이지 스크롤·당겨서 새로고침이 발생하지 않는다.
  - 규칙
    - [ ] 이동 시 모든 타일이 해당 방향 끝까지 이동하고, 같은 숫자 타일이 만나면 하나로 합쳐진다(값 2배).
    - [ ] 한 번의 이동에서 하나의 타일은 최대 1번만 합쳐진다 (예: [2,2,2,2] → 왼쪽 → [4,4,_,_]).
    - [ ] 이동으로 보드에 변화가 있을 때만 새 타일 1개가 빈 칸에 생성된다. 변화가 없는 입력은 무시된다.
  - 점수
    - [ ] 합쳐질 때마다 합쳐진 결과 값만큼 점수가 증가하고, 현재 점수가 화면에 실시간 표시된다.
    - [ ] 현재 점수 옆에 로컬 최고 점수가 표시된다 (FR-005).
  - 게임오버/재시작
    - [ ] 빈 칸이 없고 인접한(상하좌우) 같은 숫자 타일도 없으면 게임오버 화면(최종 점수, 최고 점수, "다시 하기")을 표시한다.
    - [ ] "다시 하기" 또는 게임 화면의 "새 게임" 버튼을 누르면 점수 0, 새 보드로 즉시 재시작된다.
    - [ ] 2048 타일을 처음 만들면 "성공" 안내를 표시하고, "계속하기"로 이어서 플레이할 수 있다. (확정: 계속하기 허용, 되돌리기는 MVP 제외)
  - 표시
    - [ ] 타일 숫자별로 색이 구분되고, 4자리 이상 숫자도 타일 안에 잘리지 않고 표시된다.
- 화면/흐름: 게임 화면(점수판, 최고 점수, 새 게임 버튼, 보드) / 게임오버 오버레이
- 예외 상황
  - 이동 애니메이션 중 연속 입력: 입력을 버리지 않고 순서대로 처리하거나 애니메이션을 즉시 완료 후 처리한다 (입력 유실 금지).
  - 게임 도중 새로고침/이탈 시 진행 상태는 저장하지 않는다(새 게임으로 시작). `<진행 상태 저장 여부는 미결정 - 6장>`

#### FR-004 점프 게임 플레이
- 사용자 스토리: 사용자로서, 달리는 캐릭터를 점프시켜 장애물을 피하며 최대한 오래 살아남고 싶다.
- 인수 조건(Acceptance Criteria)
  - 시작
    - [ ] 게임 화면 진입 시 "스페이스 또는 화면을 탭하여 시작" 대기 상태로 표시되고, 첫 입력에 게임이 시작된다.
  - 조작
    - [ ] 데스크톱: 스페이스바(및 ↑ 키)로 점프한다. 게임 화면에서 스페이스 입력 시 페이지가 스크롤되지 않는다.
    - [ ] 모바일: 게임 영역을 탭하면 점프한다. 탭 시 더블탭 확대·텍스트 선택이 발생하지 않는다.
    - [ ] 캐릭터가 땅에 있을 때만 점프할 수 있다(공중 점프 불가). (확정: MVP는 단일 점프만)
  - 진행
    - [ ] 캐릭터는 제자리에서 달리고, 장애물이 오른쪽에서 왼쪽으로 다가온다.
    - [ ] 장애물은 무작위 간격으로 생성되며, 현재 속도에서 항상 점프로 피할 수 있는 최소 간격이 보장된다.
    - [ ] 게임 속도는 시간이 지날수록 점진적으로 증가하며, 상한 속도가 있다.
    - [ ] 이동·속도 계산은 프레임 간 경과 시간 기준이어서, 화면 주사율(60Hz/120Hz)이나 일시적 프레임 저하와 관계없이 같은 시간에 같은 거리를 이동한다.
  - 점수
    - [ ] 점수는 생존 거리(=경과 시간 × 속도 누적) 기반 정수로 화면에 실시간 표시된다.
    - [ ] 현재 점수 옆에 로컬 최고 점수가 표시된다 (FR-005).
  - 게임오버/재시작
    - [ ] 캐릭터가 장애물과 충돌하면 즉시 게임이 멈추고 게임오버 화면(최종 점수, 최고 점수, "다시 하기")을 표시한다.
    - [ ] 충돌 판정은 보이는 그래픽보다 약간 작은 히트박스를 사용해 억울한 판정을 줄인다.
    - [ ] "다시 하기" 버튼, 스페이스, 탭으로 재시작하면 점수 0, 초기 속도로 시작한다.
    - [ ] 게임오버 직후 짧은 입력 무시 시간(예: 0.5초)을 두어 점프 연타로 의도치 않게 바로 재시작되지 않는다.
- 화면/흐름: 게임 화면(점수, 최고 점수, 게임 영역) / 시작 대기 / 게임오버 오버레이
- 예외 상황
  - 탭 전환·창 최소화 시 일시정지된다 (FR-006). 복귀 시 바로 재개하지 않고 입력을 기다린다.
  - 그래픽 에셋은 자체 제작 또는 사용 허가된 것만 사용한다 (크롬 공룡 등 타사 에셋 복제 금지).

#### FR-005 로컬 최고 점수
- 사용자 스토리: 사용자로서, 가입하지 않아도 내 최고 기록이 남아 있어서 기록 갱신에 도전하고 싶다.
- 인수 조건(Acceptance Criteria)
  - [ ] 게임오버 시 이번 점수가 저장된 최고 점수보다 높으면 최고 점수를 갱신하고 "최고 기록!" 표시를 한다.
  - [ ] 최고 점수는 게임별로 분리되어 브라우저 로컬 저장소(localStorage)에 저장된다. 키는 게임 id 기반으로 한다 (예: `mgh:{gameId}:bestScore`).
  - [ ] 새로고침, 브라우저 재시작 후에도 같은 브라우저에서는 최고 점수가 유지된다.
  - [ ] 서버로 어떤 데이터도 전송하지 않는다 (MVP).
- 예외 상황
  - 로컬 저장소를 쓸 수 없는 환경(사생활 보호 모드, 용량 초과 등): 게임은 정상 동작하고, 최고 점수는 현재 세션 동안만 유지한다. 오류 화면을 띄우지 않는다.
  - 저장된 값이 숫자가 아니거나 손상된 경우 0으로 간주하고 덮어쓴다.
  - 로컬 점수는 사용자가 임의 수정할 수 있으므로 신뢰하지 않는다 (2차 랭킹에 그대로 이관하지 않음).

#### FR-006 게임 일시정지(탭 이탈)
- 인수 조건(Acceptance Criteria)
  - [ ] 점프 게임 진행 중 탭 전환·창 최소화(페이지 숨김) 시 자동 일시정지된다.
  - [ ] 복귀 시 "계속하려면 스페이스/탭" 안내를 표시하고, 입력 시 재개한다.
  - [ ] 일시정지 중에는 점수와 속도가 증가하지 않는다.

#### FR-101 회원/로그인 (2차, 상세 미정)
- 개요: 랭킹 참여를 위한 회원 기능. 로그인 방식(이메일/비밀번호, 소셜 로그인, 닉네임만 등)은 미결정.
- 원칙: 로그인하지 않아도 모든 게임은 계속 플레이할 수 있어야 한다(랭킹 참여만 로그인 필요).

#### FR-102 점수 제출 (2차, 상세 미정)
- 개요: 로그인 사용자가 게임오버 시 점수를 score-service에 제출한다. 비로그인 사용자는 제출하지 않는다.
- 원칙: 서버는 클라이언트 점수를 그대로 믿지 않고 최소한의 검증(점수 범위, 제출 빈도 제한, 중복 제출 방지)을 한다. 부정 점수 방지 수준은 미결정.

#### FR-103 게임별 리더보드 (2차, 상세 미정)
- 개요: 게임별 상위 N명 점수와 내 순위를 조회한다. 집계 기간(전체/주간/일간), N 값은 미결정.

## 4. 비기능 요구사항
- 성능
  - 실시간 게임(점프 게임)은 중급 사양 모바일 기기(`<기준 기기 미정>`)에서 60fps를 목표로 하며, 프레임 저하 시에도 게임 속도(물리)는 경과 시간 기준으로 일정해야 한다.
  - 입력 → 화면 반응 지연이 체감되지 않아야 한다 (목표: 1프레임 이내 반영).
  - 홈 화면 초기 로딩: 모바일 4G 기준 LCP 2.5초 이하 목표. 게임별 코드는 진입 시 지연 로딩.
- 보안
  - MVP는 개인정보를 수집·전송하지 않는다. 로컬 저장소에는 점수 외 정보를 저장하지 않는다.
  - 2차부터 인증·개인정보 처리 요구사항을 별도 정의한다.
- 가용성/확장성
  - MVP는 정적 리소스 위주로 제공하여 서버 장애 지점을 최소화한다. 호스팅 방식은 미결정.
  - 게임 추가 시 기존 게임·홈 코드 수정을 최소화한다 (게임 레지스트리, architecture.md 참고).
- 호환성(브라우저/기기)
  - 데스크톱: Chrome, Edge, Firefox, Safari 최신 2개 버전
  - 모바일: iOS Safari, Android Chrome, Samsung Internet 최신 2개 버전 `<지원 하한 버전 미정>`
  - 화면 너비 360px 이상, 모바일 세로 화면 기준으로 플레이 가능해야 한다.
  - 터치와 키보드 모두 지원하며, 키보드만으로 홈 → 게임 진입이 가능해야 한다 (Tab/Enter).
- 언어: 한국어 UI `<다국어 지원 여부 미정>`
